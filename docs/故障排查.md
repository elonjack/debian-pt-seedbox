# 故障排查

先收集信息，不要立刻重装。重装可能破坏配置、做种状态和 H&R 时间。

## 1. 一键诊断

在仓库或 Release 解压目录运行：

```bash
bash check.sh
```

它会显示系统、软件版本、Swap、服务、端口、UFW、DNS、HTTPS 和已脱敏的最近日志。

## 2. HTTPS 打不开

```bash
getent ahostsv4 你的完整子域名
caddy validate --config /etc/caddy/Caddyfile
systemctl status caddy --no-pager
journalctl -u caddy -n 100 --no-pager
ufw status verbose
ss -lntp | grep -E ':80|:443'
```

首次签发证书时域名应直接解析到当前 VPS，并先使用 Cloudflare 灰云。DNS 生效后：

```bash
systemctl restart caddy
```

HTTPS 正常后才切小黄云，Cloudflare SSL/TLS 使用 Full (strict)。

## 3. 安装器提示已有 Caddy 配置

这是防覆盖保护。脚本在安装软件前就会停止，不会覆盖其他网站。

把下面站点块手动合并到现有 `/etc/caddy/Caddyfile`，域名换成自己的：

```caddy
qbt2.example.com {
	reverse_proxy 127.0.0.1:8080
}
```

然后：

```bash
caddy fmt --overwrite /etc/caddy/Caddyfile
caddy validate --config /etc/caddy/Caddyfile
systemctl restart caddy
```

## 4. 找不到首次密码

新版本把随机密码保存为 root-only 文件：

```bash
ls -l /root/qbittorrent-webui-credentials.txt
cat /root/qbittorrent-webui-credentials.txt
```

登录并修改密码后应删除该文件。如果文件已删除且忘记密码，按 qBittorrent 官方“WebUI password locked”流程恢复；不要关闭身份验证。

## 5. 登录循环或 401/403

检查：

- 使用 `https://`；
- 浏览器没有保存旧密码；
- Secure Cookie 已开启；
- 反向代理支持已开启；
- 受信任代理是 `127.0.0.1`；
- 服务器域名包含真实域名和 `127.0.0.1`；
- 系统时间正确。

```bash
timedatectl
```

不要关闭 CSRF、Host Header 或身份验证。

## 6. qBittorrent 服务失败

```bash
systemctl status qbittorrent-pt.service --no-pager -l
journalctl -u qbittorrent-pt.service -n 100 --no-pager
id qbt
ls -ld /var/lib/qbittorrent /srv/qbt/downloads /srv/qbt/incomplete
```

只在权限确实错误时修复：

```bash
chown -R qbt:qbt /var/lib/qbittorrent /srv/qbt
chmod 0750 /var/lib/qbittorrent /srv/qbt/downloads /srv/qbt/incomplete
systemctl restart qbittorrent-pt.service
```

不要使用 `chmod -R 777`。

## 7. WebUI 是否安全监听

```bash
ss -lntp | grep ':8080'
```

正常应只有：

```text
127.0.0.1:8080
```

若出现 `0.0.0.0:8080` 或公网 IP：

1. 不要给 UFW 添加 8080；
2. 在 WebUI 把 IP 改回 `127.0.0.1`；
3. 重启服务；
4. 再次检查。

## 8. Tracker 不可连接

```bash
grep PEER_PORT /etc/qbt-seedbox.conf
ss -lntup | grep 49160
ufw status verbose
```

同时检查 VPS 商家安全组，TCP 和 UDP 都要放行。NAT VPS 还需要商家端口映射；独立公网 IP 通常不需要。

## 9. 上传速度只有 KiB/s

先看该任务“用户”一列：

- `0 (N)`：当前没连接下载者，0 B/s 或很慢正常；
- `1 (N)`：只有一个下载者，对方可能只需要少量数据；
- 下载者很多但始终很慢：再检查限速、端口、线路和机器负载。

端口正确只表示别人能连接，不代表一定有人需要数据。10 Gbps 是理论端口上限，不是每个种子的保证速度。

## 10. Swap 没创建

```bash
swapon --show
free -h
grep -v '^[[:space:]]*#' /etc/fstab
ls -l /swapfile 2>/dev/null
df -h /
```

脚本在以下情况不会再创建：

- 已有正在使用的 Swap；
- fstab 已配置 Swap；
- `/swapfile` 已存在；
- `--swap-mb 0`；
- 磁盘空间不足。

这是保护行为，不是安装失败。

## 11. 磁盘满

```bash
df -h /
du -sh /srv/qbt/downloads/* 2>/dev/null | sort -h
```

只清理站点已确认 H&R 达标的任务。不要直接删除 `/var/lib/qbittorrent`，这里有任务状态。

## 12. 内存不足

```bash
free -h
swapon --show
journalctl -k | grep -i -E 'oom|out of memory'
```

处理：

- 同时活动下载保持 1；
- 全局连接数约 300，每 Torrent 约 30；
- 不安装 Vertex、Docker 等额外面板；
- 减少同时加入的种子数。

## 13. 更新后客户端不在白名单

```bash
qbittorrent-nox --version
apt-cache policy qbittorrent-nox
```

暂停添加新任务，联系站点管理组确认。不要从不明网站下载所谓“绿色版”替换 Debian 官方包。

## 14. 脚本拒绝重复安装

出现 `/etc/qbt-seedbox.conf` 已存在提示，说明该机器已由本项目安装。拒绝覆盖是为了保护现有任务。

先运行：

```bash
bash check.sh
```

不要删除配置文件来强行重装；这会绕过保护但不能修复根因。
