# 故障排查

先运行：

```bash
cd ~/debian-pt-seedbox
bash check.sh
```

不要一遇到问题就重装。重装可能丢失配置、做种状态和 H&R 时间。

## 1. HTTPS 域名打不开

检查 DNS：

```bash
getent ahostsv4 qbt2.example.com
```

安装签发证书阶段必须返回当前 VPS IPv4，并保持“仅 DNS/灰云”。HTTPS 已经正常且之后切换为小黄云时，返回 Cloudflare IP 是正常的。

检查 Caddy：

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl status caddy --no-pager
journalctl -u caddy -n 80 --no-pager
```

检查端口：

```bash
ufw status verbose
ss -lntp | grep -E ':80|:443'
```

DNS 刚修改时等待生效，再执行：

```bash
systemctl restart caddy
```

## 2. Caddy 提示已有配置，安装脚本停止

这是保护机制，说明这台 VPS 原先已经使用 Caddy 托管其他服务。不要覆盖。

把下面站点块合并到现有 `/etc/caddy/Caddyfile`：

```caddy
qbt2.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

然后：

```bash
caddy fmt --overwrite /etc/caddy/Caddyfile
caddy validate --config /etc/caddy/Caddyfile
systemctl restart caddy
```

如果不确定如何合并，先备份并寻求帮助。

## 3. 找不到首次临时密码

```bash
journalctl -u qbittorrent-pt.service -n 100 --no-pager
```

搜索 `password`。若服务未运行：

```bash
systemctl restart qbittorrent-pt.service
systemctl status qbittorrent-pt.service --no-pager
```

已修改过永久密码后，不会继续使用首次临时密码。

## 4. 登录后循环返回登录页

检查：

- 浏览器使用 `https://`；
- WebUI 的 Secure Cookie 已开启；
- 反向代理支持开启；
- 受信任代理为 `127.0.0.1`；
- 服务器域名包含实际子域名和 `127.0.0.1`；
- 系统时间正确。

```bash
timedatectl
```

不要通过关闭 CSRF、Host Header 或身份验证来处理。

## 5. qBittorrent 服务启动失败

```bash
systemctl status qbittorrent-pt.service --no-pager -l
journalctl -u qbittorrent-pt.service -n 100 --no-pager
id qbt
ls -ld /var/lib/qbittorrent /srv/qbt/downloads /srv/qbt/incomplete
```

修复目录所有权：

```bash
chown -R qbt:qbt /var/lib/qbittorrent /srv/qbt
chmod 0750 /var/lib/qbittorrent /srv/qbt/downloads /srv/qbt/incomplete
systemctl restart qbittorrent-pt.service
```

不要用 `chmod -R 777`。

## 6. Tracker 显示不可连接

检查 qBittorrent 端口是否与脚本一致：

```bash
grep PEER_PORT /etc/qbt-seedbox.conf
ss -lntup | grep 49160
ufw status verbose
```

还要检查 VPS 商家控制台中的安全组/云防火墙。TCP 和 UDP 都要放行。

如果商家提供的是 NAT VPS，需要额外做端口映射；普通独立公网 IP 不需要。

不要开启 UPnP 来代替服务器防火墙配置。

## 7. 上传速度只有 KiB/s

常见原因是没有人需要你的数据：

- `用户 0(3)`：发现 3 人但当前连接 0 人；
- 下载者已经从其他做种机获得数据；
- 种子发布太久；
- 做种者远多于下载者。

这通常不是 10 Gbps 端口故障。端口速度是能力上限，不能制造下载者和数据需求。还要理解：

- `18000 KiB/s` 约等于 17.6 MiB/s，只是上限，不是保底速度；
- `用户 4(8)` 表示连接 4 人，不代表每人都会持续向你下载；
- `用户 0(5)` 表示当前没有任何下载者连接，上传为 0 正常；
- 下载者可能同时连接大量更近、更快、数据块更多的做种机；
- 已下载完但没有人需要的内容，公网带宽再高也不会产生上传。

先检查监听和防火墙：

```bash
grep PEER_PORT /etc/qbt-seedbox.conf
ss -lntup | grep 49160
ufw status verbose
```

然后在站点确认“可连接：是”。若已经可连接，选发布 0～30 分钟、确有下载者、做种者较少的新种测试。不要拿没有下载者的旧种测试线路。

只有热门新种在多次测试中也无法上传、站点同时显示不可连接，才继续排查商家安全组、NAT 端口映射或共享线路质量。

## 8. 只有一个完整种子，为什么还能下载

其他未完成下载者各自拥有不同数据块，会互相交换。`种子 0(1)` 表示没有直接连接唯一完整种源，但仍可从下载者获取他们已有的数据块。

如果稀有数据块始终只有完整种源拥有，进度可能暂时卡住。保持运行等待，不要频繁“强制重新汇报”。

## 9. 磁盘满

```bash
df -h /
du -sh /srv/qbt/downloads/* 2>/dev/null | sort -h
```

只清理站点已经确认 H&R 达标的种子。先在 WebUI 删除任务，再按需要选择同时删除文件。

不要直接执行来源不明的批量删除命令。不要删除 `/var/lib/qbittorrent`，其中包含任务状态。

## 10. 内存不足

```bash
free -h
swapon --show
journalctl -k | grep -i -E 'oom|out of memory'
```

处理：

- 同时活动下载保持 1；
- 降低全局连接数；
- 不安装 Vertex、Docker 和其他重型面板；
- 确认 Swap 正常；
- 减少一次加入的种子数量。

## 11. 重启后会不会停止做种

服务已设置开机自启：

```bash
systemctl is-enabled qbittorrent-pt.service
systemctl is-active qbittorrent-pt.service
```

重启期间不累计做种时间；服务重新运行后会继续任务。重启前后都要检查状态。

## 12. 更新 qBittorrent 后站点不允许

Debian 安全更新可能升级客户端。升级前后检查：

```bash
qbittorrent-nox --version
apt-cache policy qbittorrent-nox
```

如果新版本不在站点白名单，不要添加新任务，先联系站点管理组。不要从随机网站下载所谓“绿色版”替换官方软件包。
