# Debian 13 PT 小白操作手册

本文从一台刚重装好的 VPS 开始，覆盖域名、安装、首次登录、添加种子、H&R、磁盘清理和多 VPS 使用。

## 0. 先理解这套结构

```text
你的浏览器
   │ HTTPS 443
   ▼
Caddy（自动证书）
   │ 本机 127.0.0.1:8080
   ▼
qBittorrent WebUI

其他 BT 用户
   │ TCP/UDP 49160
   ▼
qBittorrent 数据传输
```

8080 不应向公网开放。浏览器只访问域名的 HTTPS；BT 用户只连接单独的监听端口。

## 1. VPS 和站点确认

在安装前逐项确认：

- 系统是 Debian 13 amd64；
- VPS 服务商允许合法的 BitTorrent 流量；
- PT 站点允许 qBittorrent 5.x；
- 站点允许你的 VPS 所在机房或国家；
- 准备多台 VPS 时，站点明确允许同一账号使用多个公网 IP；
- 不要在两台 VPS 同时添加同一个私有种子，除非站点明确允许。

“连接数无限”不一定等于“公网 IP 数无限”。不确定时先联系站点管理组。

## 2. Cloudflare 创建子域名

以第二台 VPS 为例：

1. 打开 Cloudflare 对应域名。
2. 进入“DNS → 记录”。
3. 添加 A 记录：
   - 类型：`A`
   - 名称：`qbt2`
   - IPv4：第二台 VPS 的公网 IPv4
   - 代理状态：安装阶段先选 **仅 DNS（灰云）**
   - TTL：自动
4. 保存。

不要把第一台和第二台都解析到同一个 `qbt` 名称。每台机器使用独立子域名。

在 VPS 检查：

```bash
getent ahostsv4 qbt2.example.com
```

输出必须是第二台 VPS 的 IPv4。DNS 还没生效时先等待，不要反复重装。

### HTTPS 成功后能否打开小黄云

可以，但要分清两条连接：

- `https://qbt2.example.com` 是 WebUI，使用 HTTP/HTTPS 443，可以由 Cloudflare 小黄云代理；
- `49160/TCP+UDP` 是 BT 数据端口，普通 Cloudflare 代理不支持，仍然直接连接 VPS 公网 IP。

正确顺序：

1. 安装时保持灰云；
2. 浏览器确认 `https://qbt2.example.com` 能正常登录；
3. Cloudflare → DNS → 找到 `qbt2` → 点击灰云，改为“已代理/小黄云”；
4. Cloudflare → SSL/TLS → 概述 → 选择 **Full (strict)**；
5. 不要选择 Flexible，否则容易出现重定向循环或源站链路不安全；
6. 重新打开 WebUI 测试。

小黄云只能减少别人通过 DNS 直接查到源站 IP，并给 WebUI 增加 Cloudflare 的 HTTP 防护。PT Tracker 和 BT 同伴仍会看到 VPS 公网 IP，因此它不能隐藏盒子 IP，也不会提高 BT 上传速度。

如果开启后出现 526，先切回灰云，确认 Caddy 已取得有效证书，再检查 Cloudflare 是否为 Full (strict)。不要关闭 qBittorrent 的 CSRF、Host Header 或登录验证。

## 3. 真正的一行安装

使用 FinalShell 登录全新的 Debian 13 VPS。以 `root` 身份把下面一整行复制一次，把域名替换成自己的：

```bash
apt-get update -qq && apt-get install -y -qq curl ca-certificates && curl --proto '=https' --tlsv1.2 -fsSLo /tmp/pt-bootstrap.sh https://github.com/elonjack/debian-pt-seedbox/releases/download/v1.1.0/bootstrap.sh && bash /tmp/pt-bootstrap.sh --domain qbt2.example.com
```

你的第二台 VPS 示例：

```bash
apt-get update -qq && apt-get install -y -qq curl ca-certificates && curl --proto '=https' --tlsv1.2 -fsSLo /tmp/pt-bootstrap.sh https://github.com/elonjack/debian-pt-seedbox/releases/download/v1.1.0/bootstrap.sh && bash /tmp/pt-bootstrap.sh --domain qbt2.qgv.de5.net
```

这才是本文所说的“一行安装”：终端只粘贴一次、回车一次。它会：

- 安装 `curl` 和证书包；
- 下载固定的 `v1.1.0` Release Bootstrap；
- Bootstrap 下载同一 Release 的 `install.sh`；
- 校验 `install.sh` 的 SHA-256；
- 校验通过才进入安装确认。

脚本显示 SSH 端口、域名、BT 端口等摘要。全部正确后输入小写 `yes`。

如果 SSH 不是 22：

```bash
apt-get update -qq && apt-get install -y -qq curl ca-certificates && curl --proto '=https' --tlsv1.2 -fsSLo /tmp/pt-bootstrap.sh https://github.com/elonjack/debian-pt-seedbox/releases/download/v1.1.0/bootstrap.sh && bash /tmp/pt-bootstrap.sh --domain qbt2.example.com --ssh-port 你的SSH端口
```

不要把第一台 VPS 正在使用的域名填到第二台。

## 4. 安装完成后的检查

依次执行：

```bash
systemctl status qbittorrent-pt.service --no-pager
systemctl status caddy --no-pager
ufw status verbose
ss -lntup | grep -E '8080|49160'
free -h
df -h /
```

正确结果：

- `qbittorrent-pt.service` 是 `active (running)`；
- `caddy` 是 `active (running)`；
- UFW 是 active；
- SSH、80、443、49160 TCP/UDP 已放行；
- 8080 有监听，但 UFW 中没有 8080 的公网放行规则；
- Swap 已存在或系统原先已有 Swap。

## 5. 首次登录

获取临时密码：

```bash
journalctl -u qbittorrent-pt.service --no-pager | grep -i password
```

打开：

```text
https://qbt2.example.com
```

首次用户名通常是 `admin`，密码使用日志中的临时密码。登录后第一件事：

1. 点击齿轮“选项”。
2. 打开 WebUI。
3. 修改用户名。
4. 设置一个从未在其他网站使用过的强密码。
5. 保存并重新登录。

强密码至少 16 位，包含大小写字母、数字和符号。不要把密码贴到聊天或 GitHub。

## 6. 完成 qBittorrent 设置

严格按照 [qBittorrent 设置清单](qBittorrent设置清单.md) 逐项设置。特别注意：

- WebUI IP 地址改为 `127.0.0.1`；
- WebUI 内置 HTTPS关闭，因为 HTTPS 已由 Caddy 提供；
- CSRF、Clickjacking、Secure Cookie、Host Header 验证全部开启；
- 服务器域名填写 `qbt2.example.com;127.0.0.1`；
- 反向代理支持开启，受信任代理只填 `127.0.0.1`；
- DHT、PeX、本地用户发现关闭；
- BT 监听端口必须与脚本一致；
- 上传上限按站点规则设置，不要追求 VPS 端口理论速度。

保存设置后检查：

```bash
ss -lntup | grep -E '8080|49160'
```

WebUI 应只显示 `127.0.0.1:8080`；BT 端口应监听公网网卡。

## 7. 添加第一个种子

只选择你有权获取的内容，并优先用小种子测试。

初次测试标准：

- 100 MB～1 GB；
- 做种人数至少 2～3；
- 正在下载人数至少 1；
- 已完成人数至少 1；
- 磁盘至少保留 2 GiB 空闲。

站点数字常见含义：

```text
大小 | 做种者 | 下载者 | 已完成人数
```

qBittorrent 中：

```text
种子 3(6) = 已连接 3 个完整做种者，Tracker 共报告 6 个
用户 2(8) = 已连接 2 个下载者，Tracker 共报告 8 个
```

下载 `.torrent` 时：

- 直接点站点“下载种子”；
- 不要复制、公开种子链接；
- `.torrent` 和链接包含私人 passkey；
- 不要把 `.torrent` 上传到聊天、网盘或 GitHub。

在 WebUI 点左上角 `+`：

- 选择 `.torrent`；
- 保存到 `/srv/qbt/downloads`；
- 停止条件：无；
- 不勾选“跳过哈希校验”；
- 内容布局：原始；
- 所有文件完整下载，不要为了省空间只选部分文件；
- 确认后开始。

## 8. Free、50%、2X 是什么

常见优惠：

- `Free`：下载不计入站点下载量，上传正常统计；
- `50%`：实际下载 1 GiB，站点约记录 0.5 GiB 下载；
- `2X上传`：上传统计可能按双倍计算；
- `Free & 2X`：下载不计，上传可能双倍。

优惠只影响站点统计，不会减少 VPS 实际占用的磁盘或实际流量。

新人“下载 50 GB”任务需要普通计量或折扣下载。全下 Free 不会推进下载任务。

## 9. H&R 必须遵守

H&R 是 Hit and Run，即下载完立刻停止做种。

以 BTSCHOOL 2026-07-25 当时规则为例：

- 下载完成后的 10 天内累计做种达到 20 小时；或
- 该种上传量达到下载量，单种分享率不低于 1。

规则可能变化，必须重新阅读站点最新规则。

站点显示 `H&R 1/0` 通常表示：

- 1 个正在考核；
- 0 个已经违规。

没人连接你，不代表可以删除。没有上传需求时只能靠做种时间达标。

稳妥流程：

1. 下载完成后保持状态“做种”；
2. 至少保留 24 小时；
3. 到站点 H&R 页面确认“已达标”；
4. 再决定是否删除。

不要只看 qBittorrent 的总分享率，H&R 往往按单个种子计算。

## 10. 小硬盘如何循环

不要把磁盘塞满。至少保留 2 GiB 空闲：

```bash
df -h /
```

建议：

- 同时下载最多 1 个；
- 每个 500 MB～2 GB；
- 完成后持续做种；
- 只有站点确认 H&R 达标后才能腾空间；
- 一次清理一个，防止误删未达标种子。

删除前：

1. 站点确认 H&R 已达标；
2. qBittorrent 确认种子名称；
3. 右键删除；
4. 需要释放磁盘时才选择“同时删除文件”。

删除任务但不删除文件不会释放磁盘。删除文件后无法继续做种。

## 11. 为什么 10 Gbps 端口上传仍然慢

VPS 端口只是最大能力，不代表一定有下载需求。上传速度取决于：

- 当前是否有下载者；
- 下载者是否需要你拥有的数据块；
- 对方的下载速度和地理位置；
- 其他做种者的竞争；
- 站点允许的速度上限；
- 商家是否共享或限制端口。

`用户 0(3)` 表示 Tracker 看到 3 个下载者，但当前没有任何人连接你，所以速度可以是 0。

你截图里的情况：

- 正在下载的任务是 `用户 4(8)`，当前有 4 个下载者连接，但他们合计只向你请求约 `70 KiB/s`；
- 已完成的任务有 `用户 0(5)`、`0(2)`、`0(1)`，当前没人连接，所以上传为 0；
- 另一个完成任务为 `用户 5(6)`，确实有人连接，但对方可能只缺少少量数据块或同时从很多盒子下载；
- 底部 `[17.5 MiB/s]` 是你设置的上传上限，不是当前实际速度；
- `18000 KiB/s` 的配置足以跑约 17.6 MiB/s，目前几十 KiB/s 不是被这个上限卡住。

只有同时满足以下条件，才值得怀疑端口或网络配置：

1. 热门新种有多名活跃下载者；
2. 站点长期显示“不可连接”；
3. qBittorrent 的 `用户` 始终是 `0(很多)`；
4. VPS 上 `49160/TCP+UDP` 没监听或防火墙未放行；
5. 多个不同种子、不同时间都出现同样问题。

服务器检查：

```bash
grep PEER_PORT /etc/qbt-seedbox.conf
ss -lntup | grep 49160
ufw status verbose
```

正确时应同时看到 `49160` 的 TCP LISTEN 和 UDP UNCONN，UFW 也应放行 TCP、UDP。再确认 VPS 商家控制台没有额外安全组。站点显示“可连接：是”时，传入端口基本已经正常。

选种更重要：

- 发布 0～30 分钟；
- 下载者多于做种者；
- 已完成人数大于 0 更稳；
- 500 MB～2 GB；
- Free/2X Free 适合争取上传；
- 普通或 50% 适合推进下载任务。

不要通过伪造汇报、魔改客户端、限速规避或重复下载同一私有种子作弊。

## 12. 多 VPS 的正确用法

技术上每台 VPS 都可运行独立 qBittorrent，但账号规则优先：

1. 向站点确认是否允许同一账号多 IP；
2. 每台 VPS 使用独立子域名；
3. 每台使用不同 BT 监听端口不是站点要求，但便于管理；
4. 不复制 qBittorrent 配置目录到另一台；
5. 不复制 WebUI 密码；
6. 不让同一个 `.torrent` 在多台机器同时连接，除非站点书面允许；
7. 每台机器分别记录其 H&R 种子和清理日期。

如果站点不允许多 IP，第二台 VPS 可以完成系统安装，但不要向其中添加该站点种子。

## 13. 日常维护

每周检查：

```bash
bash check.sh
df -h /
free -h
systemctl --failed
```

安装安全更新：

```bash
apt-get update
apt-get upgrade
```

更新后如提示需要重启，先确保 qBittorrent 状态已保存，再：

```bash
systemctl restart qbittorrent-pt.service
systemctl status qbittorrent-pt.service --no-pager
```

正常重启 VPS 不会清除任务，但重新上线前的离线时间不计入做种时间。
