# Debian 12/13 PT 小白操作手册

本手册配合仓库 v1.2.1 使用。先读站点规则，再操作服务器。任何截图、`.torrent`、Tracker URL 和“下载链接”都可能包含你的私人 passkey，不要公开。

## 1. 先确认是否适合

准备：

- Debian 12 或 Debian 13 amd64 VPS；
- root SSH 登录；
- 至少约 10 GiB 可用磁盘；
- 一个独立子域名；
- PT 站允许的 qBittorrent 版本；
- PT 站明确允许盒子/VPS；使用多台 VPS 时还需允许多 IP。

Debian 12 官方仓库通常提供 qBittorrent 4.5.2 系列，Debian 13 提供 5.1.0 系列。两者界面文字略有差异，但本手册核心设置相同。

查看系统：

```bash
cat /etc/os-release
dpkg --print-architecture
df -h /
free -h
```

## 2. 配置域名

在 Cloudflare 为每台 VPS 创建不同的 A 记录：

```text
qbt1.example.com -> 第一台 VPS IPv4
qbt2.example.com -> 第二台 VPS IPv4
```

开始时：

- 代理状态：仅 DNS/灰云；
- TTL：自动；
- 不要给两台 VPS 使用同一个子域名。

等待解析后，在 VPS 检查：

```bash
getent ahostsv4 qbt2.example.com
```

命令中的域名必须换成自己的，返回 IPv4 必须是当前 VPS。

## 3. 一行安装

以 root 身份执行 README 中当前版本的一行命令。脚本会询问域名，输入自己的完整域名。

安装时脚本会显示预检查摘要。重点核对：

- 系统是 Debian 12 或 13；
- 域名没有写错；
- SSH 端口与你当前连接一致；
- BT 端口没有冲突；
- Swap 计划合理。

如果不确定，输入除 `yes` 以外的内容即可取消。

## 4. Swap 会不会重复添加

不会。脚本依次检查：

1. 是否已有正在使用的 Swap；
2. `/etc/fstab` 是否已有 Swap 条目；
3. `/swapfile` 是否已经存在；
4. 剩余磁盘是否足够。

任一已有配置都会保留，不会覆盖。你可以安装前后对比：

```bash
swapon --show
free -h
grep -v '^[[:space:]]*#' /etc/fstab
```

## 5. 首次登录

安装结束后查看一次性凭据：

```bash
cat /root/qbittorrent-webui-credentials.txt
```

浏览器打开文件中给出的 `https://你的域名`，用 `admin` 和随机密码登录。

脚本已经做到：

- Debian 12 不使用公开默认密码 `adminadmin`；
- Debian 13 不要求你从日志手抄临时密码；
- WebUI 只监听 `127.0.0.1:8080`；
- 外部访问只能经过 Caddy HTTPS。

登录后立刻在“选项 → WebUI”修改用户名和强密码。确认新密码能重新登录，再删除凭据：

```bash
rm -f /root/qbittorrent-webui-credentials.txt
```

## 6. 完成 qBittorrent 设置

按 [qBittorrent 设置清单](qBittorrent设置清单.md) 逐项检查。不要跳过以下项目：

- 默认下载目录 `/srv/qbt/downloads`；
- 未完成目录 `/srv/qbt/incomplete`；
- BT 监听端口与安装参数一致；
- UPnP/NAT-PMP 关闭；
- DHT、PeX、本地用户发现关闭；
- 不自动追加公共 Tracker；
- WebUI 跳过身份验证全部关闭；
- CSRF、Clickjacking、Secure Cookie、Host Header 验证开启；
- 反向代理只信任 `127.0.0.1`；
- 不设置自动停止做种。

设置后检查：

```bash
ss -lntup | grep -E '8080|49160'
ufw status verbose
```

如果你安装时改过 BT 端口，把 `49160` 换成实际端口。

## 7. Cloudflare 小黄云

先确保浏览器已经能正常打开 HTTPS。然后：

1. Cloudflare DNS 中把 WebUI 的 A 记录改为“已代理/小黄云”；
2. SSL/TLS 加密模式选择 **Full (strict)**；
3. 保持 HTTPS 重定向；
4. 再次打开域名测试。

Cloudflare 只代理 WebUI 的 80/443。BT 端口不走 Cloudflare，所以：

- BT 端口仍由 UFW 和 VPS 商家安全组直接放行；
- 不要把 Tracker 地址改成 Cloudflare 域名；
- 不要开放 8080。

## 8. 如何选择第一个种子

只选你有权获取的内容。新手先用小种测试：

- 大小约 100 MiB～2 GiB；
- 优先 Free 或折扣种；
- 至少有 1 个完整做种者；
- 最好有正在下载的人；
- 发布时间较新；
- 磁盘完成后仍至少留 2 GiB。

列表中的常见列：

```text
做种者：拥有完整文件的人
下载者：尚未完成、可能向你请求数据的人
完成数：历史完成下载的人数
```

“下载者为 0”意味着当前通常没人需要你的数据，即使 VPS 端口很快，上传也可能是 0。

## 9. 添加种子

从站点点击“下载种子文件”，保存 `.torrent` 到自己的 Windows 电脑。不要复制公开分享下载链接。

在 qBittorrent WebUI 点击左上角 `+`：

- 选择该 `.torrent`；
- 保存到 `/srv/qbt/downloads`；
- 停止条件：无；
- 跳过哈希校验：不勾选；
- 内容布局：原始；
- 选择全部文件；
- 开始 Torrent：确认后勾选或手动点击开始。

`.torrent` 含私人 passkey，不要上传到聊天、网盘或 GitHub。

## 10. 看懂 qBittorrent 数字

```text
种子 3 (6) = 已连接 3 个完整做种者，Tracker 共报告 6 个
用户 2 (8) = 已连接 2 个未完成下载者，Tracker 共报告 8 个
```

括号外是当前实际连接数，括号内是 Tracker 报告总数。

下载过程中出现上传，通常是其他下载者从你这里拿到了你已下载的数据块，属于正常现象。

## 11. 为什么只有 KiB/s

“10 Gbps 端口”只是上限，不保证每个 PT 种子都能上传到该速度。实际速度受以下因素决定：

- 是否真的有人下载；
- 对方是否选择连接你；
- 对方下载速度和线路；
- 同一批高速盒子的竞争；
- 种子是否已被大量完整做种者覆盖；
- qBittorrent 全局/单种限速；
- 站点速度限制；
- VPS 的共享带宽、CPU 和磁盘。

若列表显示 `用户 0 (N)`，你当前没有连接下载者，0 B/s 正常。端口监听和“站点可连接：是”只能证明别人可以连你，不能创造下载需求。

## 12. H&R

H&R 是 Hit and Run，即下载后过早停止做种。规则因站点而异，必须以站点当前页面为准。

安全做法：

1. 下载完成后保持“做种”；
2. 不设置自动停止；
3. 到站点 H&R 页面确认该种已达标；
4. 再决定是否删除；
5. 小硬盘一次只清理一个已确认达标的种子。

不要只看 qBittorrent 的总分享率。站点通常按单个种子的做种时间和分享率判断。

## 13. Free、50%、2X

- Free：站点通常不计下载量，上传正常计入；
- 50%：站点按一半下载量计入；
- 2X 上传：站点可能按双倍上传计入；
- Free & 2X：不计下载并双倍计上传。

优惠只影响站点统计，不会减少 VPS 实际磁盘占用和真实流量。新人任务如果要求“下载量”，全 Free 种可能不推进该项。

## 14. 小硬盘管理

检查：

```bash
df -h /
du -sh /srv/qbt/downloads/* 2>/dev/null | sort -h
```

至少保留约 2 GiB 空闲。删除前：

1. 站点确认 H&R 已达标；
2. qBittorrent 确认任务名称；
3. 右键删除；
4. 只有确实要释放磁盘时才选“同时删除文件”。

删除任务但保留文件不会释放磁盘；删除文件后无法继续做种。

## 15. 多台 VPS

每台 VPS：

- 使用不同子域名；
- 使用独立随机 WebUI 密码；
- 独立记录 H&R 和清理日期；
- 不复制 `/var/lib/qbittorrent`；
- 不把同一私人 `.torrent` 随意放到多台机器。

最重要的是先问站点是否允许同账号多 IP/多客户端。技术上能运行，不代表规则允许。

## 16. 日常维护

每周检查：

```bash
df -h /
free -h
swapon --show
systemctl --failed
systemctl status qbittorrent-pt.service --no-pager
systemctl status caddy --no-pager
```

安装安全更新：

```bash
apt-get update
apt-get upgrade
```

更新后检查 qBittorrent 版本是否仍在站点白名单：

```bash
qbittorrent-nox --version
apt-cache policy qbittorrent-nox
```

出现问题先看 [故障排查](故障排查.md)，不要直接重装。重装和误删配置可能破坏做种状态与 H&R 记录。
